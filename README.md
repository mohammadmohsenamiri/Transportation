# Transportation Management System

سامانه فارسی و راست‌به‌چپ مدیریت حمل بار، تعریف مأموریت، پایش تقریبی خودروها روی نقشه و نمایش «فرانمای وضعیت».

این ریپازیتوری مستقل از `AITaskManagement` است. آن پروژه فقط مرجع انتخاب فناوری و قواعد عمومی توسعه بوده و هیچ تغییری در آن نباید انجام شود.

## پشته فنی مبنا

- Next.js App Router و TypeScript با حالت strict
- React
- PostgreSQL و Prisma ORM
- Tailwind CSS و کامپوننت‌های Headless قابل سفارشی‌سازی
- Zod، React Hook Form و TanStack Query
- MapLibre GL JS و Turf.js؛ تمام assetها به‌صورت محلی bundle شوند
- Playwright برای آزمون‌های E2E و Vitest برای آزمون‌های واحد
- فونت Vazirmatn به‌صورت package/local، بدون CDN

نسخه‌های اولیه باید با نسخه‌های پایدار و سازگار ریپازیتوری مرجع هماهنگ باشند؛ ارتقای major version تنها در یک فاز مستقل و پس از ثبت تصمیم معماری مجاز است.

## قواعد کلیدی محصول

- کل رابط کاربری فارسی، RTL، لمسی و واکنش‌گرا است.
- تاریخ‌ها در پایگاه داده UTC/Gregorian و در UI شمسی نمایش داده می‌شوند.
- کارکرد اصلی سامانه نباید به اینترنت، CDN، نقشه عمومی یا سرویس ابری وابسته باشد.
- نقشه داخلی TMS/XYZ/WMTS منبع اصلی در محیط عملیاتی است؛ Provider جهانی فقط گزینه تکمیلی است.
- موقعیت خودروها «تقریبی» و بر اساس زمان شروع، سرعت snapshot شده و مسیر مأموریت محاسبه می‌شود؛ تا زمانی که GPS واقعی اضافه نشده نباید با عنوان موقعیت واقعی نمایش داده شود.
- Claude فقط یک فاز را در هر تغییر پیاده‌سازی می‌کند و پس از آن `docs/PHASE_STATUS.md` را به‌روزرسانی می‌کند.

## شروع توسعه

وضعیت فعلی: Phase 0، Phase 1 (ورود واقعی و پوسته محافظت‌شده)، Phase 2 (ساختار سازمانی چهارسطحی)، Phase 3 (انواع خودرو، نوع بار و ناوگان)، Phase 4 (نقشه داخلی و نمایش دفاتر/انبارها)، Phase 5 (مدیریت مسیر، CSV و ترسیم روی نقشه)، Phase 6 (تعریف مرسوله و مقصد)، Phase 7 (برنامه‌ریزی مأموریت از فرم)، Phase 8 (تعریف مأموریت از داخل نقشه)، Phase 9 (موتور موقعیت تقریبی — لایه محاسباتی pure بدون UI، طبق `docs/phase-09-simulation-engine/`)، Phase 10 (نقشه عملیاتی پایه و حرکت خودروها)، Phase 11 (جدول مأموریت، انتخاب متقابل و فیلترها) و Phase 12 (موتور زمان‌بندی — سیکر زمان زنده/تاریخی و پخش) تکمیل شده‌اند.

```bash
npm install
cp .env.example .env   # DATABASE_URL، SESSION_SECRET و SEED_ADMIN_* را پر کنید
npm run db:generate
npm run db:migrate
npm run db:seed
npm run dev
```

سپس `http://localhost:3000` را باز کنید:

- `/login` — ورود واقعی؛ کاربر Admin اولیه از مقادیر `SEED_ADMIN_USERNAME`/`SEED_ADMIN_PASSWORD` در `.env` ساخته می‌شود و در اولین ورود مجبور به تغییر رمز است.
- `/dashboard` — پوسته محافظت‌شده واقعی؛ بدون session معتبر به `/login` هدایت می‌شود.
- `/system/organization` — مدیریت CRUD ساختار سازمانی چهارسطحی (دفتر کشوری/گروه/توزیع‌کننده/انبار)؛ فقط برای نقش Admin.
- `/system/vehicles`، `/system/vehicle-types`، `/system/cargo-types` — مدیریت ناوگان، انواع خودرو و انواع بار با کارت‌های خلاصه آمادگی؛ فقط برای نقش Admin.
- `/system/map-providers` — مدیریت Provider نقشه (XYZ/TMS/WMTS داخلی یا خارجی اختیاری) با تست اتصال؛ فقط برای نقش Admin.
- `/map` — نمایش دفاتر و انبارها روی نقشه داخلی (MapLibre)؛ برای همه نقش‌های احرازهویت‌شده (Admin، بیننده وضعیت، برنامه‌ریز مأموریت).
- `/routes`، `/routes/new`، `/routes/[id]` — مدیریت مسیرها: import/export CSV، ترسیم با Click/Tap روی نقشه، نسخه‌بندی، تکثیر و غیرفعال‌سازی؛ مشاهده برای همه نقش‌ها، مدیریت فقط برای Admin و برنامه‌ریز مأموریت.
- `/shipments`، `/shipments/new`، `/shipments/[id]` — تعریف مرسوله با مبدأ انبار و مقصد (گره سازمانی یا مختصات آزاد با Tap روی نقشه)، جزئیات، ویرایش، تاریخچه و حذف نرم؛ فقط برای Admin و برنامه‌ریز مأموریت.
- `/missions`، `/missions/new`، `/missions/[id]` — برنامه‌ریزی مأموریت با wizard شش‌مرحله‌ای (مرسوله، مبدأ/مقصد، خودرو، زمان شروع شمسی، مسیر اختیاری، بازبینی و تخمین)، انتشار، ویرایش پیش از شروع، لغو با دلیل اجباری، تکثیر و تاریخچه؛ فقط برای Admin و برنامه‌ریز مأموریت.
- `/map` همچنین حالت «ساخت مأموریت از نقشه» دارد (فقط Admin و برنامه‌ریز مأموریت): انتخاب انبار مبدأ با Tap روی marker یا جست‌وجو، انتخاب مقصد با Tap روی نقشه یا ورود مختصات، سپس انتخاب مرسوله/خودرو/زمان/مسیر (شامل import سریع CSV یا ترسیم مسیر) در یک پنل — بدون ترک نقشه، با reuse کامل سرویس‌ها و اعتبارسنجی‌های فاز ۷.
- `/map` همچنین خودروهای مأموریت‌های برنامه‌ریزی‌شده را در موقعیت تقریبی (فاز ۹) با marker جهت‌دار نمایش می‌دهد؛ کلیک روی marker پنل جزئیات مأموریت (مبدأ/مقصد، ETA، پیشرفت، مرسوله) و مسیر یا خط مستقیم خط‌چین آن مأموریت را باز می‌کند؛ به‌روزرسانی خودکار هر ۵ ثانیه بدون ذخیره موقعیت در DB و با برچسب دائمی «نمای زنده محاسباتی».
- `/map` همچنین یک جدول مأموریت‌های فعال کنار نقشه (دسکتاپ/تبلت) یا در bottom sheet (موبایل) دارد که با انتخاب marker↔ردیف دوطرفه همگام است؛ فیلتر مبدأ/مقصد/نوع خودرو/وضعیت/زمان شروع/ETA/فقط‌فعال (از پنل یا context menu روی marker انبار)، جست‌وجوی سریع، مرتب‌سازی ستون‌ها و نمای ذخیره‌شده (فقط برای همان نشست مرورگر) را پوشش می‌دهد؛ فیلترها هم‌زمان روی جدول و marker‌های نقشه اثر می‌گذارند.
- `/map` همچنین یک نوار زمان (Timeline Engine، فاز ۱۲) زیر نقشه دارد: پیش‌فرض «نمای زنده محاسباتی» (بدون اقدام کاربر)؛ با drag روی نوار، دکمه‌های گام ±۵/±۱۵ دقیقه یا ورود مستقیم ساعت:دقیقه می‌توان به هر لحظه از بازه یک‌روزه جلالی جاری پرید و کل صحنه (marker‌ها + جدول) برای همان لحظه با برچسب «بازسازی زمانی» بازسازی می‌شود؛ Play/Pause با سرعت ۰.۲۵× تا ۸× زمان را به‌جلو پخش می‌کند و در پایان بازه خودکار متوقف می‌شود؛ یک دکمه «بازگشت به اکنون» همیشه به نمای زنده برمی‌گرداند؛ ورود به حالت «ساخت مأموریت از نقشه» به‌طور خودکار به نمای زنده بازمی‌گردد. هیچ موقعیتی برای این نوار در DB ذخیره نمی‌شود — فقط پارامتر `viewTime` متفاوتی به همان `GET /api/v1/map/scene` فاز ۱۰ داده می‌شود.
- `/prototype/overview` و `/prototype/map` — همچنان پیش‌نمایش رابط با fixture ثابت (`src/demo/fixtures.ts`) هستند، بدون اتصال به داده واقعی یا session.
- `GET /api/v1/missions/:id/simulate?viewTime=...` — موتور محاسبه موقعیت تقریبی (فاز ۹)؛ صفحه UI ندارد، فقط API فقط-خواندنی؛ برای هر سه نقش احرازهویت‌شده باز است. جزئیات کامل در `docs/phase-09-simulation-engine/`.
- `GET /api/v1/map/scene?viewTime=...` — صحنه دسته‌ای نقشه عملیاتی (فاز ۱۰): فهرست همه مأموریت‌های برنامه‌ریزی‌شده به‌همراه موقعیت تقریبی، محاسبه‌شده با فراخوانی موتور فاز ۹ برای هرکدام؛ برای هر سه نقش احرازهویت‌شده باز است.
